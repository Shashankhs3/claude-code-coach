# Beta Feedback Log

Real user feedback only — nothing here is invented. This file is
populated after the 0.3.x pre-release ships and people actually use it.
Keep it local to this repository; do not add telemetry to collect this
automatically (see the Master Release Pass's explicit rule against it).

Iteration discipline for the first beta:

```
observe → collect feedback → reproduce → fix → test → release patch
```

Not: one complaint → redesign everything. A single report is a data
point, not a mandate — look for a pattern across multiple reports (or a
severe enough single one — data loss, crash, privacy) before treating
something as a real priority.

## How to log an item

One entry per report, under the matching category below:

```
### [YYYY-MM-DD] Short title
- Reporter: (issue link, or "internal" if self-observed)
- What happened:
- Expected:
- Repro steps (if known):
- Status: New | Reproduced | Fixed (link commit/version) | Won't fix (why) | Can't reproduce
```
